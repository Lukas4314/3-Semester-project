\section{Communication}

% https://mosquitto.org/man/mqtt-7.html <--- cool link
% https://docs.oasis-open.org/mqtt/mqtt/v5.0/mqtt-v5.0.pdf <-- also cool

Communication between the Raspberry Pi and the PC is handled using the MQTT (Message Queuing Telemetry Transport) protocol. MQTT uses a publisher-subscriber model, where a publisher sends messages to a topic hosted on a broker, which are then delivered to all subscribers of that topic \cite{OASIS_MQTT5}.

An MQTT message consists of a fixed header, a variable header, and a payload. The fixed header contains information about the message type and control flags, while the variable header contains the topic name and a packet identifier (if QoS $>$ 0).

Examples of variable header fields for different MQTT message types used in the system are shown in Table \ref{tab:mqtt_packet_types}.

        \midrule
        CONNECT  & 0001 & 0x10 & PC establishing connection to the broker. \\
        PUBLISH  & 0011 & 0x3\_ & \makecell[l]{Pi sends audio.\\PC sends commands.} \\
        SUBSCRIBE & 1000 & 0x8\_ & \makecell[l]{Pi subscribes to \texttt{mqtt\_vel} (velocity commands).\\PC subscribes to topics \texttt{I2S0} and \texttt{I2S1} for audio data.} \\

The PUBLISH packet type is used for all application data. The last four bits of its fixed header define the DUP flag, RETAIN flag, and the QoS (Quality of Service) level.

QoS 0: The message is delivered at most once, with no acknowledgment. If lost, it will not be retransmitted.

QoS 1: The message is delivered at least once, with acknowledgment. If lost, it will be retransmitted until acknowledged.

QoS 2: The message is delivered exactly once, using a four-step handshake to guarantee no duplication.

All data in this project, both movement commands and audio, are sent with a QoS of 1 to ensure reliable delivery.

The DUP flag is used for QoS 1 and 2 messages to indicate whether the transmitted message is a duplicate of a previous attempt. The RETAIN flag indicates whether the broker should retain the last message sent to a topic. A retained message is stored by the broker and delivered immediately to any new client that subscribes to that topic.

The payload contains the actual data being transmitted. An example of an MQTT PUBLISH message structure is shown in Table \ref{tab:mqtt_publish_example_bytes}.

The maximum packet size in MQTT is 256 MB, though this can be limited by broker configuration. This project uses the Mosquitto broker, which by default imposes no packet size limit \cite{mosquitto}. Mosquitto acts as the central server that routes all messages between clients, ensuring messages are delivered to all subscribers of a topic. It also allows configuration of QoS levels and other parameters on a per-topic basis to tailor reliability for different data types.

The Paho-MQTT Python library is used to handle the low-level details of the MQTT protocol, including message construction, parsing, and network management. It enables each component to connect to the Mosquitto broker and communicate over TCP/IP, which in this project is implemented over a Wi-Fi network \cite{paho-mqtt}.
