Communication between the different components in the system is handled using MQTT (Message Queuing Telemetry Transport) protocol. MQTT uses a publisher-subscriber model, where a publisher sends messages to a topic hosted on a broker, which then is sent to all subscribers (all components that need data from that topic) \cite{OASIS_MQTT5}. %This ensures a layered architecture where different components only know about the topics they need data from, instead of all other components, allowing for modularity and easy scalability. 

MQTT messages consist of a fixed header, variable header and a payload. The fixed header contains information about the message type and flags, while the variable header contains topic name and packet identifier (if QoS $>$ 0).

The PUBLISH packet type is used for all application data. The last four bits of its fixed header is the QoS (Quality of Service) level. 

A QoS of 0 means the message is delivered a maximum of one time, with no acknowledgment, so if it is lost it will not be retransmitted. 

A QoS of 1 means the message is delivered at least once, with acknowledgment, so if it is lost it will be retransmitted until acknowledged. 

A QoS of 2 means the message is delivered exactly once, with a four-step handshake to ensure no duplicates.

All commands (Movement commands and audio data) are sent with a QoS of 1, to ensure they are received.
