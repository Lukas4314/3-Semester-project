\subsection{Sound localisation}
The algorithm for finding where the command was said was tested using real data from one of the three microphones. The input is a 4 second clip where it is known that ``come'' was said, and the output should be a $<1$ second clip of the word ``come''. This folder has five tests where ``best\_segment'' is the output and ``iteration\_1'' is the input \cite{find_voice}.

The algorithm successfully finds the index where the word ``come'' was said, but sometimes, as seen in test\_4, it finds the whole ``come here'', which based on these tests happens 20\% of the time. This, however, is not a significant problem, since both ``come'' and ``here'' have the same sound origin.

GCC Phat was tested using real time data from the 3 microphones while someone said the ``come here'' command from different points around the robot. Then the TDOA is calculated using a variety phat weight, sample size and filter settings, and the output angle was compared to the actual angle. On \cref{fig:GCC-PHAT-Real-Data-Testing} the angle error trend for different configurations is shown. Additional graphs and plots from the testing can be found in \cref{app:GCC-Phat-testing}.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.5\textwidth]{Pictures/GCC-Angle-Error-Trend-one-graph.png}
    \caption{GCC-PHAT angle error trend for different configurations tested with real data, more graphs are available in \cref{app:GCC-Phat-testing}}
    \label{fig:GCC-PHAT-Real-Data-Testing}
\end{figure}

The trend shows the best configuration was 2048 samples, a phat weight of 0.9. Similar yet worse results are seen at 0.6 to 0.8 phat weights. While a phat weight of 1.0 shows a significant decline in performance. As does the weights with and below 0.5. Smaller sample sizes also corrolates with a lower error, with 2048 samples being the best.

similarly, the effect of the filter was tested, and the results can be seen in \cref{fig:GCC-Phat-filter-vs-no-filter}. The graph shows that using the filter reduces the angle error slightly yet consistently across all weights.

\begin{figure}
    \centering
    \includegraphics[width=0.5\linewidth]{Pictures/GCC-Phat-Filter-vs-No-Filter.png}
    \caption{Comparison of GCC-PHAT angle error with and without filter for best configuration tested with real data, more graphs are available in \cref{app:GCC-Phat-testing}}
    \label{fig:GCC-Phat-filter-vs-no-filter}
\end{figure}

With this, the configuration chosen for the final system is 2048 samples, a phat weight of 0.9 and using the filter. This should result in an angle error of about 16 degrees.

\subsection{Movement control}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.7\linewidth]{Pictures/path.png}
    \caption{positional cordinates of the turtlebot messures in meter}
    \label{fig:path}

\end{figure}
The blue line shows the path which was plotted based on the difference in encoding data between the two motors, which gives the position the TurtleBot thinks it has. The orange line shows 20 observed data points in the physical world. The graph has 10 different runs.

It is noticeable that the deviation is exponential, which means the longer the motors are driving, the more inaccurate the system becomes compared to the physical world. The data also shows the randomness of the deviation, which makes it harder to correct.

Note: physical observations were made with human observation, so small inaccuracies may occur.
