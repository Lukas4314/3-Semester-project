\subsection{Sound localisation}
The algorithm for finding where the command was said was tested using real data from one of the three microphones. The input is a 4 second clip where it is known that ``come'' was said, and the output should be a $<1$ second clip of the word ``come''. This folder has five tests where ``best\_segment'' is the output and ``iteration\_1'' is the input. 

\textbf{Folder link:} \\
\href{https://github.com/Lukas4314/3-Semester-project/tree/main/find_voice}{Find-voice-test link} \\
The link can be found in \cref{app:sound-clips}.

The algorithm successfully finds the index where the word ``come'' was said, but sometimes, as seen in test\_4, it finds the whole ``come here'', which based on these tests happens 20\% of the time. This, however, is not a significant problem, since both ``come'' and ``here'' have the same sound origin.

GCC-PHAT (Generalised Cross Correlation-Phase Transform) was tested using real-time data from the 3 microphones while someone said the ``come here'' command from different points around the robot. Then the TDOA is calculated using a variety of PHAT weights, sample sizes and filter settings, and the output angle was compared to the actual angle. On \cref{fig:GCC-PHAT-Real-Data-Testing} the angle error trend for different configurations is shown. Additional graphs and plots from the testing can be found in \cref{app:GCC-Phat-testing}.

The trend shows the best configuration was 1920 samples, a PHAT weight of 0.9 and a telephone bandpass filter. Similar, yet worse results are seen at 0.6 to 0.8 PHAT weights. While a PHAT weight of 1.0 shows a significant decline in performance. As does the weights with and below 0.5. Smaller sample sizes also corrolates with a lower error, with 1920 samples being the best. Similarly, the effect of the filter was tested, and the results can be seen in \cref{fig:GCC-Phat-filter-vs-no-filter}. The graph shows that using the filter reduces the angle error slightly yet consistently across all weights.

With this, the configuration chosen for the final system is 1920 samples, a PHAT weight of 0.9 and using the filter. This should result in a mean angle error of about 16 degrees.

\subsection{Movement control}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.7\linewidth]{Pictures/path.png}
    \caption{Positional coordinates of the TurtleBot measured in meters}
    \label{fig:path}

\end{figure}
The blue line shows the path which was plotted based on the difference in encoding data between the two motors, which gives the position the TurtleBot thinks it has. The orange line shows 20 observed data points in the physical world. The graph has 10 different runs.

It is noticeable that the deviation from a straight path increases with the length the path. The data also shows the randomness of the deviation, which makes it harder to correct.

The data is based on physical observations made with human observation, so small inaccuracies may occur.

This test was done using the whole system, meaning talking to the robot and it moving succesfully. The test were done in three differnet environments: quiet, semi-noisy and noisy. The quiet environment is when nothing else is happening in the room, the semi-noise environment is when there is some background noise, and the noise environment is when a there is a lot of background noise.
The videoes showcassing the test environments can be found here:
\href{https://youtube.com/shorts/-Jo3rEJsfjg?feature=share}{Quiet Environment Video link}

\href{https://youtube.com/shorts/5an6NhUYo2M?feature=share}{Semi-Noisy Environment Video link}

\href{https://youtube.com/shorts/m3pxYh3Ubt0?feature=share}{Noisy Environment Video link}
They can also be found in \cref{app:recordings}.



A success is defined by human speech resulting in correct robot movement. Every command was tested 20 times.

For the ``come here'' command, an error of more than 30 degrees is counted as a fail.

For ``move'' and ``turn'', an error of more than 10\% of the expected path is counted as a fail.

For ``return'', an error of more than 20\,cm from the expected position is counted as a fail. Return was always made after three other movement commands.

The ``stop'' command has to be said while the TurtleBot is moving.
