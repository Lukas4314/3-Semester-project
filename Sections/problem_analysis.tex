\section{Problem Analysis}
For transcription of voice commands, a reliable and accurate speech recognition system is required. For this task, an AI solution is preferred due to the complexity and variability of human speech. OpenAI's Whisper model is chosen for this task, as it has the required capabilities and is open source, allowing for easy integration and customization. It has also scored at the high end of speech recognition benchmarks, in different models testing their WER (Word Error Rate).

For sound localization, a method to determine the direction of the sound source is needed. This requires multiple microphones set apart from one another. By using 3 microphones and comparing signals to find the phase difference between them, the direction of the sound source can be estimated. For this, the GCC-PHAT (Generalized Cross-Correlation with Phase Transform) algorithm is chosen, as it offers robust performance in noisy environments. Using the speed of sound, the position can then be estimated by triangulating from the phase differences.

For sound localization, which requires multiple microphones synchronized to the same clock, I2S microphones are used, as they inherently share a clock signal. The Raspberry Pi cannot handle more than one stereo I2S (Inter-Integrated Circuit Sound) audio channel, so an ESP32 microcontroller is needed to interface with the microphones and send the audio data, as it has two stereo I2S interfaces, totaling four mono channels. The microphones can then be mounted on a 3D-printed structure, which provides the necessary fixed geometry for triangulation.

While both the Raspberry Pi and ESP32 are on the robot, neither has the computational power to run the Whisper model in real-time. Therefore, a separate PC will be needed to handle the transcription and sound localization processing. It is important that the pc is equipped with a capable GPU, as it can accellerate the AI model inference significantly, allowing for better real-time performance.

Communication between the PC and the Raspberry Pi will be handled using MQTT (Message Queuing Telemetry Transport), a lightweight pub-sub (publish-subscribe) messaging protocol, as it is already in use for command transfer to the robot. The ESP32 does have a Wi-Fi module and can therefore also use MQTT to send the audio data. However, the efficiency and throughput of the Wi-Fi module on the ESP32 might not be sufficient to handle the audio streaming. If that is the case, both the ESP32 and the Raspberry Pi are also equipped with different wired communication protocols, allowing the audio data to be transferred first to the Raspberry Pi, which can then forward it over MQTT to the PC. While dedicated audio streaming protocols like RTP, RTSP, or WebRTC exist, MQTT's simplicity and low overhead make it suitable for this project's needs.
